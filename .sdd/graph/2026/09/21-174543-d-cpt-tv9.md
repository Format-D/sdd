Config files are read tolerantly, written patch-only, and schema-enforced only on the write path — a standing rule for every config surface sdd ships, revising the fail-loud-on-unknown-keys clause of the placement directive (20260708-184318-d-cpt-6cq), whose placement-by-whose-fact-it-is rule, overlay order, and `sdd config` surface stand unchanged.

One machine runs several sdd versions against the same files, and the user-global config configures every project at once: a user who upgrades leaves older binaries running. A reader therefore cannot distinguish a typo from a key a newer version wrote, so read-side strictness turns one legitimate new key into a dead older binary — observed live when a rebuilt binary wrote `sessions.retention` and the previous release's `sdd serve` exited at startup (20260810-144515-s-tac-8ae). Skew runs both ways and only one direction is repairable after the fact: an older binary rejecting newer data can never be fixed retroactively, only by tolerance shipped in advance.

Three commitments follow, all of them in place today (20260810-222521-s-tac-hdr). Reads never reject a key they do not know. Writes patch the document instead of rewriting it, so a binary preserves keys it cannot parse — tolerance alone would have converted a loud startup failure into silent key loss on the next write. Schema enforcement lives on the write path, where the binary knows its own schema, and judges only the key being set; validating the whole patched document refuses every write as soon as the file holds one foreign key. Unknown and misplaced keys stay visible rather than fatal: one computation reports them per location against that location's own schema, feeding the provenance view and a per-run warning.

A key sdd knows but this run does not consult is not reported at all. The global config holds what the user works with across projects and providers — a second LLM endpoint kept for testing, for benchmarking, or because a provider is unavailable today is in force somewhere, just not on this path — and the selector naming what is live sits in the same file, one line above. Reporting it would tell the user what they just wrote. The distinction that carries: sdd speaks up about a claim the user cannot check for themselves, a key it cannot place at all, and stays quiet about one that is simply true and not consulted here. This is what keeps switching providers cheap without trading away typo protection, because the two sit on different paths.
