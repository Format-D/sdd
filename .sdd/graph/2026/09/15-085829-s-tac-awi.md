Capture now publishes through a recorded session intent and survives a lost reply: the engine appends the invocation, target and pre-generated entry ID before dispatch, `CreateEntry` asks storage for an existing publication under a key hashed from session, intent sequence and discriminator before it prepares or summarizes, and `next` continues a failed publication by `retry_ref` or ends it by `cancel_ref`, which records the outcome and return position and leaves published effects in place. Delivered on branch `codex/session-capture-publication`, head commit `0814fd3c`, as PR 15. Not merged or released at the time of this record.

Session events carry accepted input, explicit preflight results, staged filename-to-blob mappings, intent and outcome, and replay reconstructs positions without dispatching. Session stores accept one of competing appends at a position, refuse empty appends and stamp timestamps. Separate blob metadata and retention ledgers are gone; collection frees a collectible session's staged bytes before deleting it. Local Git and external compositions derive the same publication identity. For a Git-backed target the graph store writes the files and the Git finalizer is the sole committer, marking the commit `SDD-Mutation: v1:<hash>` so the session handle never enters history; `local.NewRepositoryTargets` is the production wiring the CLI and its tests share. The CLI command tree moved to `internal/cliapp` with supplied streams so CLI tests run in process.

In the doing: the first commit wrote the raw session handle into commit trailers and the second introduced a second trailer name plus readers for the first's format. Review removed both, since no release ever wrote either, and kept the trailer name main has always used. Review also found the event-derived session ending overwriting a recorded one and mapping every shell end to a conclude; the derivation now takes act and reason from the shell's terminal event, checked against every ended session on one development machine, where none changed. A hosted external composition completed a real capture with an attachment and, on retry, pushed the original commit without a second capture. A real local-agent capture with the rebuilt binary is still pending.

This realizes the capture half of 20260914-001550-d-tac-n47 and the reconstruction, competing-append, cancellation and collection requirements of 20260914-113911-d-tac-wgw under 20260914-113737-d-cpt-qst, and closes neither. Summary replacement and WIP writes still use the prepared-write path; the document-level summary precondition, the WIP closing-evidence check, collection's pending-write protection, bounded automatic retry inside the request and cancellation naming its concrete residue remain open. The filesystem-only graph store without a Git finalizer recognizes retries by entry ID alone, a limitation kept deliberately.
