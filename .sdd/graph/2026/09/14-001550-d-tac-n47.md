SDD will use the append-only session log for operation intent and outcome, with storage-enforced publication identity making retries converge on the same entry. Accepted input and immutable blob references already identify what a mutation must use; recording the operation's identity lets storage prevent duplicate publication without a second ledger of frozen rendered payloads.

Preserve accepted input, explicit preflight results and staged filename-to-immutable-blob references in the session log. Before a mutating operation executes, record its originating invocation, concrete target and pre-generated resource identifiers. Reconstruct input through that intent's position, including the attachment mapping at that time. Do not copy rendered files or attachment bytes into a prepared-payload ledger.

Make preflight an explicit operation whose persisted findings and acceptance are invalidated by relevant later input. Entry creation receives its recorded ID and checks existing publication before summary generation or staged reads. Summary preparation remains inside the mutation and may repeat while publication is absent.

Use stored-event sequence for concurrency and event identity, require nonempty appends, and record event timestamps. Informational metadata updates are atomic with events; replay governs execution. A failed intent append prevents dispatch. An append conflict returns an error without a retry reference or resubmitting stale events. A persisted outcome finishes its originating operation during replay.

Publication identity is derived from session, intent sequence and a stable operation discriminator. Storage serializes historical identity lookup, operation conditions and publication. Retrying a completed publication returns it without reapplying it. Creation never allocates another entry for the same intent; unrelated additions require no whole-graph revision equality. No payload digest is required. This replaces the frozen canonical-payload, no-repeat-LLM and digest requirements of 20260730-171311-d-cpt-0cv and the retained mutation digest in 20260913-233819-d-tac-45y; immutable attachment identity remains intact.

User writes execute synchronously inside the request, with transient retries bounded by its deadline. Agent continuation uses the existing `next` surface with `retry_ref`, without resending accepted input; success returns the normal next response. Required composition completion steps run before the successful outcome, also when publication already exists. A local Git composition must finish its required commit; existing worktree files alone are insufficient. No background completion of pending user writes or separate recovery workflow is required. This replaces the pending-declaration sweep requirements in 20260730-171311-d-cpt-0cv and 20260729-082254-d-cpt-4tx.

Staged bytes remain session resources. Remove separate blob metadata and retention ledgers; collection frees resources before deleting the session. Staging failure may require resubmitting content. Later cancellation records its outcome and return position and reports remaining effects, with no Git rollback in this delivery.

Keep engine lifecycle, application operations and storage publication in their existing owners, following the subsystem boundaries of 20260712-194427-d-tac-wjq. Prove capture with an attachment, interrupted publication and same-entry retry through both local and external compositions. Exact exported signatures evolve jointly; legacy pending-intent upgrade behavior needs an explicit decision rather than a hidden compatibility subsystem.
