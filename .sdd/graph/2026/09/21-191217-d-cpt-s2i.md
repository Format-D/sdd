An error that crosses the agent boundary carries a code naming its condition, and the agent-facing prose is rendered from that code above the layer that raised it. `pkg/application` already has `ErrorCode` and an `ApplicationError` with a cause chain; this extends them to the engine's failure and refusal paths by wrapping the cause, leaving ordinary internal wrapping alone — a code registry nobody reads is its own maintenance surface.

A code is assigned where the condition is known, a frame or two above the raw failure, and never at the outer boundary: the boundary receives errors it cannot classify, and a wrong classification that looks authoritative is worse than none. An error arriving uncoded is therefore not guessed at but reported as the fourth case of 20260829-113416-d-cpt-nut — a fault in SDD itself — and counted, so the places where classification is missing are a number rather than an audit, and coding spreads by that evidence instead of by a migration.

`Message` stays, demoted: a developer-facing string behind `Error()`, for logs and debugging, and no longer what the agent reads.

Three things follow. Host-neutrality (20260707-134311-d-cpt-476) stops being a discipline that engine text can break and becomes structural, because a layer emitting a code does not write the sentence and so cannot put host command syntax in it. The failure classification of 20260829-113416-d-cpt-nut gains an inspectable form, settling what that directive deliberately left open — whether its cases need naming in code rather than only in the message — and giving the transient-versus-bad-input separation of 20260829-111247-s-cpt-xp3 a form without closing it, since a commitment does not produce behaviour. And an error becomes something a test can name rather than match as text, which is what the error-text assertions held back by 20260921-190614-d-cpt-t8i are waiting for.
