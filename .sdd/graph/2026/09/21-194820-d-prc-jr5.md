Code belongs where its concern is owned; getting it there comes before getting it to work, and getting it to work comes before making it complete.

Placement is: finding the layer a piece of code belongs to; putting it in the abstraction that owns the concern, or proposing one when none does; asking which layer may know what and who owns a concept; and defining a concept once, pointed at from elsewhere, never restated in another layer, a comment or a message. The CQRS decomposition (20260413-142300-d-cpt-l3s) says where code lives; this rule says what gives way when placement collides with function: scope. A misplaced feature passes its tests and teaches the next change to follow it; a missing feature is a visible gap.

So: name the owning layer before writing; when it has no seam, settle the seam in dialogue; when completeness needs a borrowed concern, deliver less. In review a placement finding blocks, a completeness finding is follow-up work. The review-side sibling is 20260726-200257-s-prc-cbl, where reasonable fixes compounded into machinery nobody decided.
