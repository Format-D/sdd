What an agent receives is the delivered product, so a test asserts a typed field of the response and says in its name why that field matters, with a readable snapshot test of the whole response behind it. The MCP suite does neither today: it matches substrings inside flattened strings across most of its test functions, and although it drives every tool, no test asserts a complete response — so the serves fixed by 20260921-185706-d-tac-t6u could be wrong in every structural respect while the suite stayed green. The measured inventory, the fixture's contents and the response sizes are in [test surface evidence](./21-190614-d-cpt-t8i/test-surface-evidence.md).

**Intent first, snapshot behind it.** The primary assertion inspects a typed field; the snapshot catches what no assertion anticipated. A snapshot test never stands alone, because it couples everything and states no intent — on its own it reports that something changed and not whether it mattered. Snapshots are verbatim and readable, rendered so prose diffs line by line; regeneration is one command and the git diff is the review. A hash is rejected for reporting only that something moved, which is what `TestToolContractSnapshot` does today.

**Substrings retire.** Each is read for what it was trying to say, then becomes a typed assertion carrying that intent, is dropped where the snapshot now holds the shape, or moves to the layer that authors the prose it matched. Those matching error text are the exception: they cannot become typed assertions while an error offers nothing to assert but its wording, and giving errors an assertable identity changes production code and is decided separately, so they wait on that decision rather than on this one.

**Snapshot tests live where the transport is owned, and claim only the transport.** They belong in `pkg/mcpapp` over the synthetic procedure fixture its own tests write, per 20260819-152950-d-prc-h1m, and guard the response envelope; behaviour of the procedures SDD ships stays with the `internal/proctest` suites that exercise them against the real application. This leans against that directive's own evidence — an MCP test passing against a simplified fixture while the shipped procedure went unexercised — so the claim is bounded rather than assumed: a snapshot here proves what the transport returns for a given serve, never that a shipped procedure produces that serve. A stubbed application root was rejected in favour of the fixture, because faking the wide session contract `pkg/mcpapp` depends on would freeze a hand-built idea of what the application produces, and an assumed shape is the defect. None of this is outer validation, which still needs a real agent the implementer did not shape (20260716-155256-s-prc-686).

**Determinism comes from ports, not scrubbing.** Tests stub what already exists — clock, session store, staged blobs, access, pre-flight findings, the git finalizer — and entry-ID generation becomes such a port, because identifiers other fields must agree with cannot be scrubbed without the snapshot ceasing to prove they agree. The session handle is aliased per distinct value in the renderer instead, leaving its generator untouched.
