When the agent's own retries of a failed operation have stopped helping, the served text tells it to put both continuations to the user by name, retry or cancel, instead of saying only that the user decides. The fixed prose of 20260919-141340-d-tac-qws becomes:

> This operation did not finish. Tell the user in a sentence. Retry, saying so, when trying again can help. When it cannot, or has stopped helping, put both choices to the user: retry, or cancel. It can stay pending until they choose. Retry is safe: it reuses the recorded input, and effects already applied are recognized, not repeated. Cancel leaves what exists in place.

Why the change: on 2026-09-22 the hosted slice 3 exercise in Claude Desktop Cowork held every commit request of the test repository with a fault, so publication failed before anything was written and every retry failed the same way. The agent retried three times, told the user that reads worked and writes did not, left the operation pending as an open thread and offered a later retry. It never named cancel. The user knew cancel existed only because he had built it; anyone else would have sat with a pending draft. The prose said "the user decides" and described cancel only as a property, "cancel leaves what exists in place", never as a choice to present, and the agent followed it literally. The handover was incomplete by the text, not by the agent's judgment: a user decides only among the options put to them.

What stays from 20260919-141340-d-tac-qws: the agent retries on its own first and the user is named only at the edge, because a question for every glitch teaches the user the tool is fragile; one text for every operation; the safety sentence; the structured fields beside the prose. Only the edge sentence changes, so this sharpens that directive in place rather than replacing it. Rejected: leaving the wording to the agent, since the same agent that retried without a word before the prose existed now stopped without a word about cancel, and a fixed text exists precisely to carry what judgment drops. Fulfilled when the engine's pending-operation constant carries the new text and the MCP snapshot tests of the pending serve show it, at the moment of failure and after resuming a session.
