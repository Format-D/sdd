SDD commits to reaching any inference provider that speaks the OpenAI chat-completions protocol, because a provider's data-protection terms — EU hosting, a data-processing agreement, zero retention — decide whether a project may put real work through SDD at all, independently of how good its models are.

A graph carries a project's actual reasoning, so where those requests land is a precondition rather than a preference: a team whose rules forbid sending that material to a US-hosted endpoint cannot adopt SDD however well it otherwise works. The need arrived from outside the core pair — a user requiring an EU gateway under a data-processing agreement found the `openai` provider hardwired to OpenAI's own URL, with only `ollama_endpoint` configurable, after examining a hosted-Ollama route first and judging it unusable on the same data-protection grounds, then accepting the gateway at higher cost. It landed as an outside contribution across both repositories (`networkteam/gollm#1`, `networkteam/sdd#16`).

Breadth comes from the protocol, not from a vendor list: one configurable base URL on the `openai` provider reaches any gateway or self-hosted service implementing the same protocol, with auth on the standard bearer header. That was already SDD's reach mechanism on the embedding side, where the compatible base URL stayed configurable throughout, and the library evaluation reached the same conclusion from the other end — even local runtimes are reached through a compatible base URL rather than a native binding (20260612-120423-s-cpt-jzo). The chat path was the outlier, so this names what was already the design rather than opening a new direction. Per-vendor adapters were rejected: each is maintenance surface we own and a protocol we must track, where the compatible-protocol route adds neither — and patching the gollm fork rather than swapping libraries stays that evaluation's path.

What this binds: a provider path may not hardcode a vendor's URL, and wherever provider support grows the base URL stays configurable — a new integration with a fixed endpoint violates this observably. What SDD does not take on is certifying providers or carrying compliance claims for them; it makes them reachable and the user chooses on their own terms, which is why no approved-provider list belongs in the code. This sits inside the LLM boundary directive (20260830-234501-d-cpt-q6n), whose rule that a config schema is each host's private concern holds here: reachability is a field on the host's own config schema, not a new element of the public contract. Working this commitment is also what raised the rule for provider keys that are configured but not consulted on the current path (20260921-174543-d-cpt-tv9).
