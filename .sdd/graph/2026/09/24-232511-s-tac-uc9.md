Three small deviations in served guidance and the tool surface, observed in 20260924-120119-s-tac-h61:

- The implementation setup (20260706-170000-d-prc-imp) tells the agent to declare the work branch "unless the session framing already names it as the base", a check it cannot make: the framing it last saw names the old base, and the next arrives only with its next call. Agents declared anyway, which did no damage in these runs.
- The record step tells the agent to start capture with `closes`, but `start_procedure` declares its params as an open object that does not type the seedable state, so every run first sent `closes` as a string and was rejected.
- Sessions reached a natural stopping point without the agent offering to wrap up, which the session shell (20260704-100000-d-prc-dlg) asks for; seen in these runs and often elsewhere.
