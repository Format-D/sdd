SDD will trust storage adapters to preserve the immutable bytes they accept and will remove duplicate attachment-integrity checks from application reads and writes. Attachment-page digests, staged-blob digests, attachment-materialization digests, and size revalidation add fields and hashing without protecting against any valid application event. Exact-revision acquisition provides read consistency, and an immutable blob ID provides write consistency. A mismatch means storage corruption or an adapter returning different bytes for one blob ID, both outside application responsibility.

`MutationBatch.Digest` remains. It identifies the durable operation for retry, conflict detection, and reconciliation by binding the canonical documents, attachment blob IDs, destinations, and other mutation fields; it does not re-verify storage. The staged-blob conformance suite will instead require each issued blob ID to remain bound to the bytes originally staged.

This narrows delivery-as-convergence (20260730-171311-d-cpt-0cv): an immutable blob ID identifies attachment bytes, while the mutation digest identifies the operation. It follows the subsystem-owned public boundary (20260712-194427-d-tac-wjq) and applies the proportionality rule surfaced by defensive machinery without a credible threat model (20260726-200257-s-prc-cbl).
